# 股票趋势分析工具到 Freqtrade 的策略迁移说明

## 1. 结论与范围

已审阅 `趋势分析实时买卖点工具-v4.0-发行版`。它不是一个单一的“买卖策略”，而是由趋势、量价、形态、唐奇安突破、CAN SLIM 评分、缠论分析和一层风险后处理组成的股票分析系统。

其中 **趋势、成交量确认、唐奇安通道和 ATR 风控是可迁移到加密货币的核心**。本仓库已加入第一版 `CryptoTrendBreakoutStrategy`：它针对 5 分钟加密货币 K 线，使用 1 小时趋势过滤、BTC 市场环境过滤、相对成交量、OBV 与唐奇安突破做多。它是独立、透明的重实现，不依赖原工具的 API、许可证或股票数据。

以下部分不能原样迁移：

| 原工具能力 | 不能直接使用的原因 | 币圈替代方案 |
| --- | --- | --- |
| A 股主力资金净流入、超大单 | 交易所 OHLCV 不提供统一的主力资金口径 | 相对成交量、OBV、CMF；若交易所提供，再单独接入 taker buy/sell 数据 |
| 换手率 | 加密资产流通量、合约未平仓量口径不统一 | 相对成交量、成交额、资金费率或 OI（需独立数据源） |
| 上证指数、涨跌家数 | A 股市场结构与 24×7 币圈不同 | `BTC/USDT` 的 1 小时 EMA20/EMA60 作为风险环境；后续可加入市场广度 |
| 涨停、跳空缺口 | 币圈没有日涨跌停，连续交易几乎没有传统交易时段跳空 | 删除涨停规则；缺口仅作为异常波动研究项，不作为入场条件 |
| 分时午休聚合 | 币圈没有午休、交易不断档 | 直接使用交易所 5 分钟 OHLCV |
| 缠论实时买卖点 | 分型和笔的确认天然依赖后续 K 线，直接交易容易产生未来函数/信号回绘 | 先作为图表研究项；若进策略，必须把信号向后延迟到确认 K 线收盘后 |

## 2. 原项目的工作方式

原项目启动一个本地 HTTP 服务，数据来自腾讯、新浪和东方财富。主接口获取约 250 根日线、实时行情、资金流、上证指数以及市场涨跌家数，再把数据送入信号引擎。信号引擎的输出不是直接下单，而是“评分 + 文本解释 + 建议计划”。

主要调用链如下：

```text
股票 K 线 / 实时行情 / 主力资金 / 上证指数
    → trend / volume_price / pattern / breakout / canslim
    → 五模块加权评分
    → 硬否决、软否决、市场环境调仓、盈亏比检查
    → 买入 / 强烈买入 / 观望与入场、止损、目标价建议
```

缠论日线和分时模块是独立分析链路，主要用于看板标注，并没有被作为五模块总分的直接输入。

## 3. 内置策略的详细拆解

### 3.1 趋势模块：均线趋势评分

输入为收盘价序列，使用 SMA20 和 SMA60。均线方向比较最近 5 个有效均线值；斜率绝对值超过起点值的约 0.2% 判为向上或向下。

| 子项 | 条件 | 分值 |
| --- | --- | ---: |
| MA20 方向 | MA20 向上 | 30 |
| MA60 方向 | MA60 向上 | 25 |
| 价格位置 | 收盘价高于 MA20 | 15 |
| 长均线位置 | 收盘价高于 MA60 | 10 |
| 共振 | 最近 20 个交易日收益为正 | 20 |

趋势强度为以上分数之和。价格在上升的 MA20 之上判为“上升”；价格在非上升 MA20 之下判为“下降”；其余为震荡。该模块还尝试在最近 20 根 K 线找递增低点来绘制上升趋势线，但该趋势线更适合可视化，不建议作为第一版自动交易条件。

**币圈迁移**：保留“价格在上升的快慢均线之上”的思想，但用 1 小时 EMA20/EMA60 过滤 5 分钟交易，避免把 5 分钟噪声当成趋势。

### 3.2 量价模块：价格、成交量、OBV 与资金流

原工具先计算 8 日价格变化：高于 +2% 判涨、低于 -2% 判跌。成交量方向由“最近 3 日均量”与“此前 5 日均量”比较得出，变化超过 ±30% 才判增量或缩量。

| 模式 | 方向 | 基础置信度 |
| --- | --- | ---: |
| 价涨量增 | 看涨 | 80 |
| 价涨量平 | 看涨 | 55 |
| 价涨量缩 | 看涨 | 60 |
| 价平量增 / 平 / 缩 | 中性 | 50 / 20 / 35 |
| 价跌量增 | 看跌 | 75 |
| 价跌量平 / 缩 | 看跌 | 50 / 60 |

OBV 按收盘上涨加成交量、下跌减成交量计算，使用约 8 根的斜率判断上升、下降或走平。实时量比相对前 5 日均量修正置信度：小于 0.5 减 3；0.5–1.5 加 2；1.5–2 加 7；大于等于 2 加 12。股票特有的资金流还会按连续三日主力净流入/流出以及单日异常净流入调整 ±10 或 ±15。

**币圈迁移**：第一版保留相对成交量和 OBV，入场要求相对成交量至少 1.20、OBV 高于其 EMA。主力资金规则不采用，因为不同交易所没有可比的“主力”口径。

### 3.3 形态模块：价格结构与目标价

该模块按头肩、双顶双底、三角形、箱体、旗形、跳空、圆弧底的顺序检测，最多返回前三个形态。它使用局部高低点，因而许多形态只有在若干根后续 K 线出现后才得到确认。

| 形态 | 检测窗口 / 关键条件 | 方向与目标 |
| --- | --- | --- |
| 箱体 | 最近 20 根高低振幅 5%–25%，价格接近上沿 | 偏多；目标 = 上沿 + (上沿 - 下沿) |
| 双底 | 最近局部低点相隔至少 5 根、两底价差不超过 3% | 看涨；目标 = 颈线 + (颈线 - 底部) |
| 双顶 | 两个局部高点价差不超过 3%，且跌破颈线才输出 | 看跌；目标 = 颈线 - (顶部 - 颈线) |
| 头肩底 | 三低点，中间最低、两肩误差不超过 8% | 突破颈线后看涨；目标 = 颈线 + (颈线 - 头部) |
| 头肩顶 | 三高点，中间最高、两肩误差不超过 8% | 跌破颈线后看跌 |
| 三角形 | 30 根内前后半段高低点斜率关系 | 上升三角偏多、下降三角偏空 |
| 上升旗形 | 前 15 根上涨，后 15 根振幅不超过 8% | 偏多；目标 = 旗形上沿 + 旗杆涨幅 |
| 圆弧底 | 60 根内价格与成交量呈圆弧 | 仅提示，未给固定目标 |

**币圈迁移结论**：形态可以保留为研究与图表标记，但不进入第一版自动开仓。原因是小周期币价波动更高，简单的局部极值规则误报会很多；而且必须严格延迟信号，避免使用尚未确认的局部高低点。

### 3.4 突破模块：海龟交易法则

这是最适合迁移的部分。它定义：

```text
TR = max(high - low, |high - previous_close|, |low - previous_close|)
N  = 最近 20 根 TR 的简单均值
```

原工具有两个系统：系统一为 20 日唐奇安通道，系统二为 55 日通道；通道都明确排除当前 K 线。向上突破通道上沿表示多头入场，初始止损为入场价 - 2N；价格每上升 0.5N 加一单位；最后加仓价再减去 2N 是移动止损。原系统一还使用 10 日通道离场，系统二使用 20 日通道离场。

**币圈迁移**：第一版保持“当前收盘突破前序通道”这一无未来函数规则，但针对 5 分钟周期做了简化：48 根（4 小时）上轨入场、24 根（2 小时）下轨离场；10% 硬止损是交易所异常或流动性事件的最终保护。分批加仓、2N 入场价移动止损待完成独立回测后再加入。

### 3.5 CAN SLIM：七维动量评分

原版并非严格的基本面 CAN SLIM，而是技术价格、成交量和资金流的代理评分。

| 维度 | 原规则概述 | 权重 |
| --- | --- | ---: |
| C | 20 日和 5 日涨幅，取高分 | 15% |
| A | 120 日涨幅 | 10% |
| N | 120 日新高、接近 250 日高点或杯柄突破 | 25% |
| S | 相对前 5 日成交量的供需代理 | 5% |
| L | 60 日和 250 日收益分档 | 20% |
| I | 5 日主力资金净流入/流出 | 15% |
| M | 上证指数 MA20/MA60 与近 20 日上涨天数 | 10% |

总分取加权和的整数部分，评级从 A+ 到 D。原版会在 M 分低于 40 时给出市场偏空警告。

**币圈迁移**：C、A、N、S、L 都可以在 OHLCV 上重构；I 需要交易所成交方向或链上/合约数据；M 由 BTC 市场状态替代。第一版没有把这个评分直接用于下单，以免在没有可靠 I 数据时制造“伪精确”分数；BTC 1 小时趋势先承担 M 的风险过滤职责。

### 3.6 五模块聚合与风险后处理

原版总分计算为：

```text
总分 = 趋势×25% + CAN_SLIM×20% + 突破×20% + 量价×20% + 形态×15%
```

形态分从 50 分开始，每个看涨/看跌形态按 `±置信度 × 0.2` 调整。总分大于等于 75 为强烈买入，大于等于 60 为买入，否则观望。置信度是总分和“分数不低于 60 的模块数量”的函数，风险等级则对下降趋势、看跌量价、低 M 分和止损信号累加风险点。

其后处理进一步执行：跌破 MA20、价跌量增、OBV 下降为硬否决；MA20 向下、受压 MA60 为软否决；M 分低时降低仓位；盈亏比低于 1 时拒绝开仓。

**币圈迁移**：第一版把这种“先有方向，后有否决”的思想改为明确的条件交集：只有币对趋势、BTC 趋势、通道突破、成交量、OBV、ADX 和 RSI 风险过滤同时满足才进场。这样更适合 Freqtrade 回测，也更容易定位每笔交易的原因。

### 3.7 缠论日线与分钟线

两个缠论模块共有的主流程是：K 线包含关系合并 → 顶/底分型 → 至少相隔 4 根合并 K 线的笔 → 中枢 → MACD 面积背驰 → 一、二、三类买卖点。

- **包含处理**：新 K 线和当前段互相包含时，按上一方向取高低点极值。
- **分型**：三根合并 K 线中，中间高点高于两侧为顶分型；中间低点低于两侧为底分型。
- **笔**：从首个分型开始，顶到低为向下、低到顶为向上；异类分型需至少间隔 4 根合并 K 线才闭合一笔。
- **中枢**：连续两笔的价格重叠区间 `[ZD, ZG]`；后续笔突破 ZG/ZD 标记为向上/向下突破。
- **背驰**：同方向新笔创更极端价格，且该笔 MACD 柱绝对面积小于上一同向笔，才认定背驰。
- **一类点**：背驰向下笔终点为一买，向上笔终点为一卖；日线置信度约为 `clamp(round(94.5 - 35 × 面积比), 55, 92)`。
- **二类点**：一类点后的回调未破前低/前高。
- **三类点**：中枢突破后的回踩/反抽没有回到中枢。

分钟模块先把逐分钟数据按股票交易时段聚合为 5 分钟 K 线；这一步不适用于连续交易的币圈。更关键的是，分型必须等到右侧 K 线出现才能确认，笔和中枢又需要更多后续 K 线。因此不能把图上已标出的历史点直接当作当时可交易信号。

## 4. 当前 Freqtrade 集成实现

新增文件：`user_data/strategies/CryptoTrendBreakoutStrategy.py`。

| 层级 | 第一版规则 | 原系统对应思想 |
| --- | --- | --- |
| 交易周期 | 5 分钟 | 原系统的短线执行层 |
| 币对趋势 | 1 小时 EMA20 > EMA60，EMA20 五小时斜率为正 | 趋势模块 + MA 共振 |
| 市场环境 | BTC/USDT 1 小时 EMA20 > EMA60 | CAN SLIM 的 M 维度 |
| 触发 | 收盘突破前 48 根 K 线最高价 | 唐奇安系统 |
| 量价确认 | 当前成交量 / 前 20 根均量 ≥ 1.20，OBV 高于 OBV EMA | 量价模块 |
| 趋势确认 | 5 分钟 EMA20 > EMA60，ADX ≥ 18 | 趋势强度过滤 |
| 过热/异常过滤 | RSI < 72，ATR/收盘价在 0.2%–10% 之间 | 风险后处理 |
| 离场 | 收盘跌破前 24 根低点、EMA20 下穿 EMA60，或 1 小时趋势转弱 | 唐奇安退出 + 趋势否决 |
| 最终保护 | -10% 硬止损，盈利后启用追踪止损 | 原版 2N 止损思想的保守替代 |

策略只做多，适合高流动性 USDT 现货对。它会请求 BTC/USDT 的 1 小时数据，因此配置的 `stake_currency` 应为 `USDT`，交易所也必须提供 `BTC/USDT`。

## 5. 验证与启用步骤

不要直接把新策略用于实盘。先在本地或服务器的同一份历史数据上完成以下三步：

```bash
# 1. 确认策略被 Freqtrade 发现
freqtrade list-strategies --strategy-path user_data/strategies

# 2. 下载/补齐 5m 与 1h 数据（交易对请按自己的白名单替换）
freqtrade download-data --exchange binance --timeframes 5m 1h \
  --pairs BTC/USDT ETH/USDT SOL/USDT

# 3. 回测；显式指定策略，避免仍在使用原来的 SampleStrategy
freqtrade backtesting --config user_data/config.json \
  --strategy CryptoTrendBreakoutStrategy --timerange 20240101-
```

回测至少应跨越上涨、下跌和震荡三个市场阶段，并计入实际手续费、滑点和交易所最小下单额。通过后，先使用 `--dry-run --strategy CryptoTrendBreakoutStrategy` 观察数周；只有在干跑结果、交易频率、最大回撤和日志行为均符合预期时，再考虑实盘。

当前 `docker-compose.yml` 的命令行仍固定为 `--strategy SampleStrategy`，这是刻意保留的安全默认值。准备启用时，将其中的策略名改为 `CryptoTrendBreakoutStrategy`，然后仅重启容器；策略文件在 `./user_data` 挂载目录中，不需要在云服务器构建镜像。

## 6. 后续迭代建议

1. 先建立基准：仅测试当前趋势突破策略，记录收益、交易数、胜率、利润因子、最大回撤和按币种表现。
2. 为 BTC 市场环境增加市场广度：例如白名单中上涨币种比例，但要避免在 `populate_indicators` 中反复请求数据。
3. 单独实现并测试 CAN SLIM 的 C/A/N/S/L 子分；I 分只有在可靠的交易所成交方向、OI 或资金费率数据可用时再启用。
4. 缠论只在“确认后的 K 线”上生成信号，并为每个分型加入确认延迟；必须做逐根 K 线回放测试，验证没有未来函数。
5. 对不同交易所、现货和合约分别回测。若要做空，应先以独立策略验证空头版本，而不是把多头条件简单取反。

## 7. 多空策略、杠杆与自动做空开关

在原有只做多策略之外，新增独立策略 `CryptoTrendBreakoutLongShortStrategy`。它继承多头条件，并增加做空确认：当前币种与 BTC 的 1 小时 EMA20 均低于 EMA60、EMA20 向下，5 分钟收盘跌破前 48 根 K 线低点，同时满足放量、OBV 低于 OBV EMA、ADX 不低于 18、RSI 高于 28 且 ATR 波动率在 0.2%–10% 区间。空单在突破前 24 根 K 线高点、5 分钟 EMA20 上穿 EMA60，或 1 小时趋势恢复时退出。

做空只适用于合约模式，推荐使用 USDT 永续合约格式，例如 `BTC/USDT:USDT`、`ETH/USDT:USDT`，并将白名单限制在 BTC、ETH、SOL 等高流动性主流币。不要把现货交易对直接用于做空策略。多头和空头必须分别回测，分别观察交易次数、胜率、最大回撤、资金费率影响和极端行情表现。

状态页的“自动做空”按钮只在 `trading_mode=futures` 时显示。关闭后只阻止新的空单信号，已有空仓仍会按策略退出；该开关是运行时设置，重启或重新加载配置后以配置文件为准。接口为受保护的 `POST /api/v1/short_enabled`，请求体为 `{ "enabled": true }` 或 `{ "enabled": false }`。

杠杆控件与自动做空开关位于同一处。杠杆只影响新开的合约仓位，已有仓位不会被修改；最终杠杆会被限制在交易所允许的最大值以内。杠杆越高，价格小幅反向波动越容易触发保证金风险，建议先用逐仓 2 倍 dry-run，并在纳入手续费、滑点、资金费率后再考虑实盘。

使用多空策略时，将容器或启动命令中的策略名改为：

```bash
--strategy CryptoTrendBreakoutLongShortStrategy
```

## 8. 授权与风险说明

所审阅的发行版带有机器绑定许可证和付费软件提示，且未附明确的源代码再分发许可。因而本仓库的策略没有复制其受保护代码、许可证逻辑或数据接口；只采用了均线、OBV、唐奇安通道等公开交易概念并进行了独立实现。若未来希望直接复用原项目的专有源码、名称或商业数据源，应先取得著作权人明确的书面授权。

所有技术指标都只是历史数据上的规则，不构成投资建议，也不保证收益。加密货币波动和流动性风险通常高于股票；任何实盘前都应完成回测、干跑、仓位限制及交易所风控检查。


## 9. 全局杠杆与前端调整

杠杆支持已经放在 Freqtrade 通用交易层，不绑定 `CryptoTrendBreakoutStrategy`。配置中可设置 `leverage`，所有未被手动强制指定杠杆的新合约入场都会使用该值；交易所的单交易对最大杠杆仍会进行最终限制。

前端机器人状态页在 `trading_mode=futures` 时显示“全局杠杆”控件。提交后只影响新开的合约仓位，已有仓位的杠杆不会改变；现货模式不会显示该控件。页面调整通过受保护的 `/api/v1/leverage` 接口应用到运行中的机器人。若希望机器人重启后仍保持设置，请同时把数值写入 `user_data/config.json`，例如：

```json
{
  "trading_mode": "futures",
  "margin_mode": "isolated",
  "leverage": 2
}
```

建议先使用逐仓 2 倍，并在开启实盘前重新下载合约 K 线、计入资金费率和手续费完成回测。`stoploss` 是按杠杆后的交易盈亏比例生效的，杠杆越高，同样的价格波动对保证金的影响越大。
